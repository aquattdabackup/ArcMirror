## Production RPC diagnosis and fix

The earlier production failures are real historical observations, retained in the [maintenance review](../maintenance-review-2026-10-07.md). Vercel CLI confirmed no production environment overrides, so the application uses the source defaults: Arc primary RPC, followed by dRPC, with dRPC for optional traces. Each contacted provider must pass chain ID 5042 validation.

Safe server diagnostics recorded incomplete transaction/receipt pairs from provider index 0 for all five owner cases. Index 1 returned complete pairs. The old adapter could stop at the incomplete primary response. The corrected adapter continues to another chain-valid provider and retains a complete provider bundle; it never combines a transaction and receipt from different providers. Optional block failures preserve receipt evidence, and all attempts share a bounded analysis deadline.

The observations came from deployment `dpl_7p9V66xr6oGaxZttjXVzW8UJgpJr` / source `9ab920c`. The final deployment changes only a stale homepage sentence and uses the same RPC code. A second all-five comparison and full browser suite passed against the final deployment. This establishes the application-level failure and recovery; the primary provider's internal reason for returning missing data is unknown.

Logs contain provider index, outcome and transaction/receipt presence only. They exclude endpoint URLs, credentials and raw provider error text. Logger failures cannot alter analysis.
